NextLA.gemm — Method
gemm(A::CompressedFTLRMatrix, B::CompressedFTLRMatrix;
     maxrank, rank_multiple=0, r_required=10, ...)

Return a compressed approximation to alpha * op(A) * op(B). ARA discovers ranks in private fixed-width staging, which is compacted before return. Operands must use regular-grid tiling. Tensor-core modes require stored widths, maxrank, and rank_multiple to satisfy the backend rank quantum.

Examples

julia> using NextLA.TileLowRank, LinearAlgebra

julia> n = 1024; K = [div(i - 1, 256) == div(j - 1, 256) ? 0.0 : 1/(1 + abs(i - j)) for i in 1:n, j in 1:n];

julia> A = CompressedFTLRMatrix(K, 256; maxrank=64, tol=1e-6, rel=true);

julia> P = NextLA.gemm(A, A; maxrank=64, tol=1e-6, rel=true);

julia> Pd = uncompress!(zeros(n, n), P);

julia> maximum(ranks(P)) <= 64 && norm(Pd - K * K) / norm(K * K) < 1e-4
true

NextLA.TileLowRank.RunCoupling — Type
RunCoupling{Fixed}

Retained state for a fixed-column or fixed-row run, physically ordered by ARA slot and swap-compacted by swap_run_members!. Both directions use S = V_A'W_B and the same three-stage sampler:

proj   = shared' * Om                       # H (:column) or G (:row)
sketch = (Fixed === :column ? S : S') * proj # T (:column) or W (:row)
Y      = member[p] * sketch[p]               # same reduction either way

Complementary packing makes the fixed factor stack zero-copy and the swept stack member-specific. Fixed columns right-sample; fixed rows left-sample, so apply_run! changes only the middle transpose.

Member stacks have nonuniform offsets and require pointer-batched GEMM. Member and beta descriptors are swap-tracked; scratch descriptors are reused without swapping; pointer APIs require a descriptor for every operand. The caller-owned Y descriptor is created by apply_run!. apply_corange! runs once after convergence and uses view batches.

NextLA.gemm! — Method
gemm!(C, A::AbstractMatrix, B::CompressedFTLRMatrix; ...)

Compute C := alpha·op(A)·op(B) + beta·C. The mirrored two-stage lowering fuses dense-panel-times-Uₖⱼ contractions over an output-row run before applying the column-packed Vₖⱼ stack to dense C.

Examples

julia> using NextLA.TileLowRank, LinearAlgebra

julia> n = 1024; K = [div(i - 1, 256) == div(j - 1, 256) ? 0.0 : 1/(1 + abs(i - j)) for i in 1:n, j in 1:n];

julia> B = CompressedFTLRMatrix(K, 256; maxrank=64, tol=1e-6, rel=true);

julia> A = rand(n, n); C = zeros(n, n);

julia> NextLA.gemm!(C, A, B; workspace=2^20);

julia> norm(C - A * K) / norm(A * K) < 1e-5
true

NextLA.TileLowRank.gemm_maximum_workspace_bytes — Method
gemm_maximum_workspace_bytes(A, B; transA='N', transB='N') -> Int

Largest workspace, in bytes, that the dense-output gemm!(C, A, B; workspace) uses for C := op(A)·op(B); a larger workspace is accepted but not used beyond this.

A and B are both CompressedFTLRMatrix or both TLRMatrix; transA and transB select op as in gemm!. For CompressedFTLRMatrix operands the result is the byte count that schedules the whole product as one run with the cheaper fold. For TLRMatrix operands it is the larger of that value for the off-diagonal parts and the bytes that hold every off-diagonal/dense-diagonal cross-term intermediate at once.

Examples

julia> using NextLA.TileLowRank, LinearAlgebra

julia> n = 1024; K = [1/(1 + abs(i - j)) for i in 1:n, j in 1:n];

julia> A = TLRMatrix(K, (256, 256); maxrank=64, tol=1e-6, rel=true);

julia> hi = gemm_maximum_workspace_bytes(A, A);

julia> C = zeros(n, n);

julia> NextLA.gemm!(C, A, A; workspace=hi);

julia> hi >= gemm_minimum_workspace_bytes(A, A) && norm(C - K * K) / norm(K * K) < 1e-5
true

NextLA.TileLowRank.build_compressed_ftlr_foldleft_run — Method

FoldLeft companion: T^L_ikj = U_ik S_ikj, then C_ij += [T^L_i1j ... T^L_iqkj]·[Z_1j';...;Z_qkj'], concatenating over k on the right. For every output column j, the T arena stacks all rows in the run vertically into one run_height × gamma_j matrix, letting Stage 3 share Z_j across the run and issue one GEMM per j rather than one per (i,j).

source
NextLA.TileLowRank.build_compressed_ftlr_foldright_run — Method

Execute one FoldRight CompressedFTLR row run: T^R_ikj = S_ikj Z_kj', then C_i += [U_i1 ... U_iqk]·[T^R_i1j;...;T^R_iqkj], concatenating over k on the left. T is packed (i,j,k)-order so each row is already the Stage-3 rho_i × (qn*bn) stack, letting Stage 3 issue one wide GEMM per row.

source
NextLA.TileLowRank.CompressedMixedGemmAnalysis — Type
CompressedMixedGemmAnalysis

Reusable symbolic metadata for CompressedFTLRMatrix × dense → dense and dense × CompressedFTLRMatrix → dense, returned by analyze_compressed_gemm(C, A, B; workspace, ...) when exactly one of A, B is a CompressedFTLRMatrix.

It is bound to the objects C, A, B and workspace, to transA/transB, the compute policy, and a copy of the compressed operand's ranks; gemm!(C, A, B; workspace, analysis, ...) throws an ArgumentError if any of these differ. Dense values, factor values, alpha and beta may change between calls. The workspace must hold at least one fused run: the sum of the compressed operand's stored ranks times sizeof(T) bytes. close(analysis) releases the prepared descriptors; a finalizer also does this.

Examples

julia> using NextLA.TileLowRank, LinearAlgebra

julia> n = 1024; K = [div(i - 1, 256) == div(j - 1, 256) ? 0.0 : 1/(1 + abs(i - j)) for i in 1:n, j in 1:n];

julia> B = rand(n, n); C = zeros(n, n);

julia> ws = DenseGemmWorkspace(A, 2^20);

julia> analysis = analyze_compressed_gemm(C, A, B; workspace=ws);

julia> NextLA.gemm!(C, A, B; workspace=ws, analysis);

julia> B .*= 2;

julia> NextLA.gemm!(C, A, B; workspace=ws, analysis);

julia> close(analysis);

julia> norm(C - K * B) / norm(K * B) < 1e-5
