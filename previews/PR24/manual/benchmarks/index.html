Benchmarks

Speed of the recursive routines, dense and mixed precision, against the vendor libraries on one GPU. Measured on an NVIDIA GB10 (NVIDIA DGX Spark) with Julia 1.10.14, 1.13.4, last run 2026-11-24.

  • Numbers are GFLOP/s (higher is better): the routine's standard flop count divided by the fastest of up to five timed calls, after an untimed warm-up.
  • Mixed-precision columns use the containers of NextLA.MixedPrecision. F16/F32 means the off-diagonal blocks are stored in Float16 and the diagonal leaves in Float32. The leaves are 4096×4096, so at n = 4096 there is no split and the matrix is one leaf in the leaf type.
  • The GB10 runs Float64 at about 400 GFLOP/s on every library, so lower precisions are where the speed is.
  • — means not measured.

Choosing precisions automatically

adaptive_precisions picks the storage type of each level from a tolerance ε. It was run on 8 test matrices of size n = 16384 (kernel matrices, block-graded matrices and randsvd matrices with condition numbers 10² to 10¹⁰), with 4096×4096 leaves. Speed-up is the vendor Float64 time divided by NextLA's (median over the matrices); error is the largest over the matrices (solve residual for the factorizations, relative error for GEMM).

εUsual choiceCholesky: speed-up vs cuSOLVER, errorLU: speed-up vs cuSOLVER, errorGEMM: speed-up vs cuBLAS, error
1e-04F16/F16/F641.1×, 1e-07 (3 of 8 not SPD)1.2×, 4e-075.3×, 3e-05
1e-08F32/F32/F641.0×, 9e-10 (1 of 8 not SPD)1.1×, 9e-107.7×, 5e-07
1e-12F64/F64/F640.8×, 8e-170.9×, 8e-171.5×, 7e-14

Cholesky can fail with PosDefException when Float16 (or, for the worst-conditioned matrix, Float32) off-diagonal blocks are chosen: adaptive_precisions bounds the storage error in norm, but rounding can still make the matrix lose positive definiteness. LU and GEMM do not have this problem.
